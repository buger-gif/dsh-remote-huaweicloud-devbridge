# 架构决策记录（ADR）

> 拍板过的取舍记在这里：**选了 A，为什么不是 B**。规则与模板在本文件，
> 不另抄到别处；架构现状写 `docs/architecture.md`。

**下一个号：0001**

## 什么时候写

有被否掉的备选方案、翻了原先的判断、或引入了会长期约束后续改动的前提。
普通实现细节不需要 ADR，写进 spec 的「方案」即可。

## 文件与状态

- 命名 `NNNN-短名.md`，取上面的「下一个号」并 +1。
- `proposed/` 待拍板 → `implemented/` 已采纳 → `rejected/` 已否决。
  状态行必须与所在目录一致（`scripts/verify_docs.py` 会查）。
- `implemented/` 是冻结区：不回改。要翻案就写一份**新** ADR，说明旧决策为什么不再成立，
  并在 `docs/architecture.md` 里就地改写现状。

## 模板

```markdown
# NNNN · 一句话决策

- 状态：proposed（proposed / implemented / rejected）
- 日期：YYYY-MM-DD

## 背景
## 决策
## 备选
## 后果
```

四个小节都必须有：「备选」至少写一条被否掉的方案与否决理由，「后果」写清代价与新增的约束
（例如多一个端口、多一份要维护的产物）。

## 已有决策

暂无。仓库初始化时确定的基础取舍（只绑回环、令牌即密钥、零第三方运行时依赖、
同源控制面）记在 `docs/architecture.md §设计取舍`；后续若要翻案，另起 ADR。
