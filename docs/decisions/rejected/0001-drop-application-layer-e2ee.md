# 0001 · 不做浏览器侧的应用层端到端加密

- 状态：rejected
- 日期：2026-11-05

## 背景

远控链路必须经过华为云 DevBridge 中继。中继在边缘终止公网 TLS，能看到到达
`127.0.0.1:gatePort` 的明文 HTTP，因此聊天正文、工具输出、审批内容与 DSH 启动令牌
对中继可读。目标原本是让中继「看不见内容」。

约束条件三条同时成立：**手机端只有一个浏览器**（不安装带外客户端）、**保留 DSH 原生
UI**（不自制远控页）、**中继不可信**。在此约束下评估了应用层加密方案，并已落地过
ECDH P-256 / HKDF-SHA256 / AES-256-GCM 的密码学核心与互操作测试。

## 决策

**不提供应用层端到端加密**，把 DevBridge 明确定位为数据通道，并在
`README.md`、`SECURITY.md`、`docs/architecture.md` 中一律声明「中继可见明文」。
不保留默认未启用的加密设施：密码学核心与对应单测一并移出仓库，避免被误读成已生效。

判断依据：浏览器侧的信任根只能是它下载代码的那个通道，而这个通道正是中继。

- 密钥可以带外传递——二维码里的 URL fragment 不会进入 HTTP 请求行，中继拿不到。
- 但**处理密钥的代码**（引导页、Service Worker、DSH 前端）全部经中继下发。
  中继改写一次脚本，就能在正确加密的同时把密钥外传；此时密文正常、公钥指纹校验
  照旧通过，且**没有任何可检测的信号**。
- 结论：这层加密只能防被动对手，防不了主动对手。而防主动对手必须引入带外可信客户端，
  与「手机只有一个浏览器」直接冲突。

在三条约束同时成立时，不存在既透明又真正可信的应用层加密。这是 Web 的信任根限制，
不是实现工作量问题——继续投入只会得到一个看起来安全、实际不安全的设施。

## 备选

| 方案 | 否决理由 |
| --- | --- |
| Service Worker 透明加密 + `window.WebSocket` 包装 | 只防被动留存、不防脚本篡改；需接管同源 HTTP 与 `/api/remote.mux`，DSH 升级即可能失配；加密层故障会 fail-closed，远控直接打不开 |
| 只加密 REST 与 mux 载荷、静态资源保持明文 | 覆盖面同样取决于那份可被篡改的下发脚本，收益上限不变而复杂度仅略降 |
| 让 DevBridge 只做 TCP 透传、网关自己终止 TLS | 实测不成立：公网 HTTPS 由华为云边缘终止，浏览器拿到 `CN=*.hwtunnel.com` 证书，本机自签证书到不了浏览器 |
| 注入 shim 接管 fetch / WebSocket / EventSource | 最重的一条：要跟随 DSH 前端内部实现，升级即碎，且仍不防篡改 |
| 带外本地代理 / WireGuard / 小程序充当客户端 | 真能防主动篡改，但要求手机安装或改用另一台电脑，与约束冲突 |
| 自建 VPS 做 TCP 转发 + 本机 Let's Encrypt 终止 TLS | 优雅、零前端改动，但引入域名与服务器，偏离「只用华为云」的定位 |

## 后果

- **中继及其代理日志、审计流水、备份能看到全部明文内容。** 这是已知且公开声明的风险，
  不再用「将来会加密」模糊它。
- 可用性因此更好：没有加密层，就没有 fail-closed 导致的「远控打不开」，也不必在
  DSH 升版后追着改 WS 帧格式。
- 对外表述成为硬约束（已写入 `AGENTS.md` 设计铁律）：不得把本项目描述为「端到端加密」
  「中继不可解密」「已受保护」。被问到内容保密时，正确回答是**换数据面或换客户端**，
  而不是加一层代理加密。
- 移除了一个约 140 行的安全模块与其测试，负向测试面同步收缩；密码学实现不再由本项目
  维护。
- 若将来放开「手机可安装客户端」或「允许自建公网入口」，重新评估时**新起一份 ADR**，
  本文件作为已否决方案的理由留存，不再改动。
